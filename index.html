Une extension open-source par JetBrains.

Andrei Bituleanu - 29/09/2026

Pourquoi et par qui?

Pourquoi TestSpark existe.

TestSpark est un plugin expérimental pour IntelliJ par JetBrains pour utiliser une IA pour écrire ses test units.

Il utilise une interface unique intégrée au workflow pour rassembler plusieurs méthodes bien distinctes pour chercher des tests unitaires. IA générative, algorithme d'optimisation et exécution symbolique.

Stratégie 1

Génération par LLM.

Le modèle doit comprendre le code, mais aussi l’intention métier derrière son comportement.

Entrée

Code source sélectionné par le développeur

Modèles

OpenAI ou Google AI, avec un token d’accès fourni par l’utilisateur

Résultat

Tests unitaires pertinents, suggérés selon le contexte du code

MUTATION

Le LLM peut aussi faire de la mutation pour vérifier les assertions : « Est-ce que mon test détecterait si cette partie du code était incorrecte ? »

CONTEXTE ESSENTIEL

Un test peut passer tout en étant faux. Sans comprendre l’intention, le LLM peut reproduire dans ses assertions un bug ou une erreur humaine déjà présente dans la méthode.

Boucle de validation

Le test se corrige en boucle.

TestSpark utilise le retour d’IntelliJ pour donner au LLM le contexte dont il a besoin pour réécrire le test.

Stratégie 2

EvoSuite fait évoluer les tests.

Il ne comprend pas le code comme un LLM : il essaie, mesure la couverture et conserve les entrées les plus utiles.

CODE À TESTER calculPrix.java 
int calculPrix(int age, boolean membre) {
  if (age < 18)
    return 5;

  if (membre)
    return 8;

  return 10;
}

Essais initiaux

1 / 3
30, false 45, false 22, false
✓ adulte non membre × mineur · adulte membre
mesure → modifie

Suite améliorée

3 / 3
15, false 30, true 30, false
✓ mineur · adulte membre ✓ adulte non membre
COUVERTURE

« Est-ce que mon test est passé dans cette partie du code ? »

Faire évoluer signifie ici modifier ou combiner les tests candidats — pas modifier le programme testé.

EvoSuite, sans IA générative

C'est un algorithme qui ne comprend pas comme une IA.

Il essaie des valeurs, exécute le code et mesure si une nouvelle branche a été atteinte.

CONDITION À EXPLORER if (age < 18) return 5;
01 age = 30

condition fausse

02 age = 25

même chemin

03 age = 18

toujours faux

04 age = 17

nouvelle branche

CE QU’IL OBSERVE

false → false → false → true

CE QU’IL NE SAIT PAS

« 18 ans correspond à l’âge adulte. »

EvoSuite garde age = 17 parce que cette valeur augmente la couverture, pas parce qu’il connaît la notion de majorité.

Stratégie 3 · Kex

Kex crée des chemins de conditions complexes.

Il suit le programme avec une valeur inconnue, sépare les chemins à chaque if, puis calcule une entrée pour chacun avec l'appel du solveur SMT.

01 · ENTRÉE INCONNUE

Variable symbolique

total = X

X remplace une valeur que l’on ne connaît pas encore.

→
02 · EXÉCUTION

Le programme rencontre un if

if (X >= 50)

Kex suit le code sans choisir tout de suite une valeur.

→
03 · DEUX CHEMINS

Conditions à satisfaire

GratuitX >= 50
5 €X < 50
→
04 · SOLVEUR SMT

Il résout les conditions

Le solveur cherche une valeur concrète qui rend chaque condition vraie.

→
05 · TESTS

Valeurs trouvées

X = 50→ 0 €
X = 49→ 5 €

En bref : Kex ne devine pas les valeurs : il calcule celles qui permettent d’ouvrir chaque chemin du programme.

Kex · Exemple concret

Les chemins en ensemble de conditions.

int calcul(int x) {
  if (x > 10) {
    if (x == 42) return 100;
  }
  return 0;
}
x <= 10→x = 0
x > 10 ET x != 42→x = 11
x > 10 ET x == 42→x = 42
Solveur SMT

Kex lui donne chaque condition. Le solveur renvoie une valeur concrète pour créer le test correspondant.

Guide de choix

Choisir selon le problème et contexte.

Il n’y a pas de meilleure stratégie dans tous les cas : chacune répond à un besoin différent.
